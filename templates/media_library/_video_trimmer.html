{% load i18n %} {% comment %} The video trimmer: the player, a strip of the video's frames and two handles that mark the stretch to keep. Nothing else: no audio, filters or text. Opened with a ``video-trim-open`` window event whose detail is ``{url, duration, maxSeconds, maxBytes, size, mode, filmstripUrl, title, onConfirm}``: ``maxSeconds`` / ``maxBytes`` are the destination's limits (null for none), ``size`` the file's bytes, and ``mode`` "compress" when only the size is over (the whole video fits the time: confirming as it opens recompresses it, the handles are optional) or "trim" (the default), and ``onConfirm(start, end, report)`` returns a promise that settles when the trim is done; a rejected one shows its message here. Meanwhile the caller calls ``report({phase, percent})`` (phase: sending, queued, preparing, trimming, saving) and the modal draws it as a bar, so the person sees the request go out, the cut run and the result being stored. It can be closed while the work runs on the server; closing never cancels it. The frames come from ``composer.views.media_filmstrip`` (cached per video, fetched once per open). ``inline`` renders it in the page instead of a modal (the library's edit screen, which opens it from its own x-init). {% endcomment %}
